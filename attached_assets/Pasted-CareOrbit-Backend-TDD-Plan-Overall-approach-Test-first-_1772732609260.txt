CareOrbit Backend TDD Plan

Overall approach





Test-first development for all backend features: write tests → run and see them fail (RED) → implement minimal code → run and see them pass (GREEN).



Azure SDK isolation via thin service wrappers (e.g. AzureVisionService, AzureOpenAIService, etc.), with all tests mocking only wrapper methods (except DB-level encryption and audit constraints).



Safety-critical behavior (auth, RBAC, drug interactions, care gaps) receives dedicated security and false positive/negative test suites before implementation.



Postgres + pgcrypto used for PII encryption; Key Vault provides secrets, and tests validate correct usage via SQL-level assertions where appropriate.

Mermaid view of document/interaction path

flowchart TD
  client[Client] --> apiDocs[api_documents_upload]
  apiDocs --> docPipeline[process_document]
  docPipeline --> visionService[AzureVisionService]
  docPipeline --> languageService[AzureLanguageService]
  docPipeline --> blobService[AzureBlobService]
  docPipeline --> phigBuilder[phig_builder]
  phigBuilder --> searchService[AzureSearchService]
  phigBuilder --> summaryRoute[api_summary_generate]

CI strategy





Stage 1 (fast, critical): pytest -m 'not phase2 and not phase3 and not demo_only and critical' for safety-critical clinical tests.



Stage 2 (default Phase 1): pytest -m 'not phase2 and not phase3 and not demo_only' for Phase 1 suite.



Stage 3 (extended): include slow and phase2/phase3/demo_only markers for full regression.
