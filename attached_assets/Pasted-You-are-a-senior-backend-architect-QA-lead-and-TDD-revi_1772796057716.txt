You are a senior backend architect, QA lead, and TDD reviewer for CareOrbit.

Your task is to create a detailed IMPLEMENTATION PLAN for generating production-grade test cases for NEW onboarding/profile-completion features in CareOrbit.

Context you must follow
CareOrbit is a healthcare web platform with:
- FastAPI backend
- PostgreSQL with pgcrypto
- Azure-hosted services
- RBAC + audit trail + refresh-token auth
- existing production-style test suite (unit, integration, functional, security, business logic, E2E)

Existing MVP-aligned facts to respect
1. Registration currently creates a user and then creates an EMPTY patient_profiles row.
2. users already supports:
   - preferred_language
   - medical_literacy_level
3. patient_profiles already supports:
   - date_of_birth
   - gender
   - blood_group
   - height_cm
   - weight_kg
   - emergency_contact_name
   - emergency_contact_phone_encrypted
   - city
   - state
   - country
4. PII like DOB/phone/emergency contact phone must be handled with pgcrypto / encryption-aware SQL patterns.
5. Audit trail is append-only and must log important actions like registration and profile updates.
6. Age should be DERIVED from date_of_birth, not stored as a static field.
7. Family dashboard and personalization logic may use age and gender from profile data.
8. Current patient profile update request already includes fields like date_of_birth, gender, blood_group, height_cm, weight_kg, city, and state.

New feature goal
We want to add mandatory onboarding/profile-completion signals that improve personalization and model output quality:
- Mandatory:
  - date_of_birth
  - gender
  - preferred_language
  - medical_literacy_level
- Optional / nice-to-have:
  - blood_group
  - height_cm
  - weight_kg
  - city
  - state
  - country
  - emergency_contact_name
  - emergency_contact_phone
  - prefer_not_to_say option for gender

Product requirement
The user should provide these fields either:
A. at registration, OR
B. at first login / first profile completion step

The implementation plan must compare both options, recommend one, and explain why from:
- product UX
- backend complexity
- security/privacy
- testability
- MVP alignment
